# M0 manual QA checklist

The M0 exit criterion is "Tom daily-drives it for streaming". These are the checks that
back that claim; they mirror the failure modes lugu exists to fix, so run them against
the real server on a real phone, not an emulator.

**Lines marked ✅ are now automated** and run on every push against a seeded Audiobookshelf
container — see [instrumented.md](instrumented.md). They are kept here rather than deleted,
because the checklist is the argument for why each is worth checking, and because a machine
checking it on an emulator is not a phone on a real network. Skip them on a routine pass.

## Sign-in and mirror

- [ ] A bare host name (`audiobooks.example`) is accepted without a scheme.
      The parsing is unit-tested, including an auto-capitalised `Https://`; what is not
      automated is that a real hostname resolves and answers
- [ ] **A plain-HTTP address on the LAN works**, and says before the password is sent that
      it is unencrypted. New on 17 August: until then Android refused the connection below
      the HTTP client and lugu reported "could not reach that server" for an address that
      was correct
- [ ] ✅ A wrong password says so, and does not say "cannot reach server" — `SignInTest`
- [ ] ✅ After sign-in the library grid fills; the sync counter shows progress.
      **There were two bugs in this line.** On 17 August `refresh()` mirrored the libraries
      and none of their items; later the same day, nothing called `refresh()` at all after
      signing in, so the mirror waited for the Library tab to be opened. `SignInTest` now
      asserts the items reach Room with no tab tapped. Still worth doing once by hand,
      because what was measured was an emulator against a container
- [ ] Force-stop the app, turn on airplane mode, reopen: the full library still renders
      and does **not** show the login screen
- [ ] ✅ Multiple libraries appear as chips and switching them works — `LibraryGridTest`

## Playback

- [ ] A book starts within a couple of seconds and the notification appears
- [ ] Position on the player screen matches the notification
- [ ] A multi-file book crosses a file boundary without the position resetting
- [ ] Skip back 10 s three times in quick succession moves back exactly 30 s
- [ ] Podcast episode playback works and is tracked separately from the podcast item

## Position durability (the point of M0)

- [ ] Play for a minute, pause, kill the app from recents, reopen — position kept
- [ ] Play, then `adb shell am kill io.github.lightheaded.lugu` mid-playback, then press
      play on a headset — the right book resumes at the right position with no UI opened.
      **Do this one.** lugu declared no `MediaButtonReceiver` until 17 August, so on a modern
      phone there was nothing for the press to arrive at once the process was gone. The
      receiver is declared now and the fix is *unproven*: `:harness` is meant to demonstrate
      it and cannot yet
- [ ] **And at the right speed.** Set the book to 1.5x first: the remembered speed used to
      be read only on the path that goes through the app, so a headset press after a kill
      brought a 1.5x book back at 1x. It is applied on the resumption path now, and this is
      the only place that says whether it worked
- [ ] Reboot the phone, press play on a headset — same result
- [ ] Airplane mode: listen for five minutes, pause, wait, re-enable network — the
      server shows the new position within a minute (outbox drained)

## Progress conflicts

- [ ] Move the position forward on another device (web UI), then open the item in lugu:
      lugu adopts the newer position and shows the "moved from another device" banner
- [ ] Tapping **Undo** on that banner returns to the earlier position and the server
      accepts it
- [ ] Listen offline in lugu while the web UI is *behind*; on reconnect the server ends
      up with lugu's newer position, not the stale one

## Housekeeping

- [ ] ✅ No crash on rotation on any screen — `RotationTest` rebuilds eight of them and
      asserts each is still the screen it was. What it cannot see is a *layout* that breaks
      in landscape, which is worth a look rather than an assertion
- [ ] Dark theme and dynamic colour look right
- [ ] TalkBack reads the transport controls and the position slider.
      The slider used to announce a percentage, which on a forty-hour book is four hours
      wide; it now says the position and the length. The grid's progress bars said nothing
      at all and now say "62% listened". Both are asserted, but only a person with TalkBack
      on can say whether the whole screen reads sensibly in order
