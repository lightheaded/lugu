# Rules for agents (and humans) working in this repo

This repository is public. It was audited and its history rewritten before
publication to remove private and identifying material. These rules exist so that
work done after that audit does not quietly reintroduce what it removed. They apply
to code, docs, tests, comments, commit messages and issue text alike.

## Privacy — never in this repository

- **No server addresses, credentials, tokens, or unredacted API captures.** Dev
  credentials live only in the gitignored `local.properties`. Live captures go
  through `scripts/capture-api.sh`, which redacts them; quote only redacted output.
  Example hosts are always `*.example` domains; example IPs only RFC1918.
- **No real library data.** No actual book, series, podcast or author names, no
  narrator names, no item counts from a real library — not in docs, not in test
  fixtures, not in code comments. Use the established invented set: *Lighthouse
  Wakes / Lighthouse Falls* by *James T. R. Corven*, narrated by *Jefferson Vale*,
  in *The Breakwater* series; the *Riverton* series for sequence tests; *The
  Tidelands* for a series with no number; *Example Series #N* in docs. Real
  measurements may be described in proportions ("about a third of items"), never in
  absolute counts or with named examples.
- **No home-infrastructure detail.** Never name the VPN, proxy, DNS setup, tunnel
  configuration or anything else about the network the dev server sits behind.
  Describe network faults generically: "a misconfiguration on the network path".
- **Identity**: the first name "Tom" is fine in docs. Full name, employer, personal
  email addresses, home directory paths and device identifiers are not.
- **Build secrets go in `secrets.enc.yaml`, encrypted with SOPS** (`.sops.yaml` holds
  the rule). Edit with `sops secrets.enc.yaml`; never write a decrypted copy into the
  working tree. The age key is dedicated to this repo and used for nothing else — a
  shared key would tie this repo to whatever else it encrypts. CI reads the decrypted
  values from repository secrets, so a rotation has to be applied in both places.
  A value that reaches the APK (the Sentry DSN does) is recoverable by anyone with a
  build: encrypting it keeps the account id out of the source, and is not a substitute
  for a rate limit on the service side.
- The pre-commit hooks (gitleaks, pii-guard) are a backstop, not the defence. If
  something sensitive does get committed, it must be scrubbed from history — not
  just from HEAD — before the next push.

## Legal and licensing — keep it compliant

- The project is **GPL-3.0-or-later**, copyright **lightheaded**. Keep the
  copyright line and the license section in the README.
- Keep the README's **non-affiliation disclaimer**. "Audiobookshelf" is someone
  else's name: use it descriptively only, never their logo or branding.
- Every dependency must carry a GPL-compatible license (everything today is
  Apache-2.0). The **licenses screen** (Settings → About → Open source licenses) is
  generated by the AboutLibraries plugin on `:app` from the real dependency graph —
  do not remove the plugin, and new dependencies need no manual attribution step.
- In `app/build.gradle.kts`, bundled `META-INF` license files are resolved with
  `pickFirst`, not `exclude` — a copy of the license text ships in the APK. Keep it
  that way.

## CI — keep it hardened

- Workflow permissions are **read-only by default**; only the release job (which
  runs on `main` alone) has `contents: write`. New jobs get no write access unless
  they publish something.
- The `wrapper-validation` step stays: the wrapper jar is committed, and the check
  proves it is the one Gradle published.
- Secrets are referenced only in the release job, and a missing secret skips the
  release rather than failing the build.

## Housekeeping

- All commits are signed; the pre-push hook refuses unsigned ones. Never bypass it
  with `--no-verify` — fix the commits instead.
- `local.properties`, keystores, `.env*`, `.claude/` and `build/api-capture/` are
  gitignored and must stay that way.
- This is a greenfield project: keep every dependency at its **latest stable** —
  libraries, the Gradle wrapper, and the GitHub Actions in `ci.yml`. When touching
  the version catalog or the workflow, check for and take available stable bumps
  (never alphas/betas), and let CI prove them. A deprecation warning in a CI log is
  a work item, not noise.
